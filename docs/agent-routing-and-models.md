# كيف تعمل الوكلاء والأدوات والنماذج في Sky Nexus Hub

## المسار العادي بعد الإصلاح

في الدردشة العادية، تمر الرسالة النصية أولًا إلى `chat-fast`، المشغّل في `supabase/functions/chat-fast/index.ts`. النموذج السريع الحالي هو Cerebras `gpt-oss-120b` عبر `callCerebras`، مع `reasoning_effort: low` وبث OpenAI-compatible SSE. لا يوجد اتصال أولي منفصل لتصنيف الرسالة؛ النموذج نفسه يبدأ الرد ويقرر هل يجيب مباشرة أم أن المطلوب يحتاج إلى قدرات المسار الكامل.

إذا قرر أن المهمة تحتاج أدوات أو بحثًا حيًا أو إنشاء وسائط أو تنفيذًا، يصدر النموذج العلامة الداخلية `[[MEGSY_ESCALATE_TO_FULL_CHAT]]`. عميل البث في `src/lib/chat/fastChat.ts` يحجز هذه العلامة ولا يعرضها، ثم يسمح لـ`src/lib/streamChat.ts` باستكمال التنفيذ في مسار الدردشة الكامل. بذلك يكون قرار التصعيد من مخرجات النموذج، لا من مطابقة كلمات مثل «صورة» أو «فيديو» في الواجهة. أما الإجابات النصية المباشرة فتُعرض token-by-token.

هذا التصعيد يذهب إلى مسار `chat-alibaba` الكامل، وليس إلى جلسة AgentSky/OpenClaw مباشرة. استدعاء AgentSky مستقل حاليًا ويحدث عند اختيار وكيل صراحةً أو متابعة جلسة AgentSky قائمة. لا يصدر قرار fast الحالي اسم وكيل متخصص كوجهة؛ فهو يختار إجابة نصية أو تنفيذًا كاملًا فحسب.

الأوضاع التي يختارها المستخدم صراحةً تظل لها أولوية: اختيار وكيل أو نموذج، وضع الصور/الفيديو، البحث العميق الصريح، وضع الكمبيوتر، وأي رسالة تكمل محادثة وكيل أو سجل أدوات. كذلك لا تزال المرفقات تمنع Fast Chat؛ فالتحقق الحالي في `chat-fast` نصّي فقط، ولا ينبغي الخلط بين هذا القيد وبين «قرار» اتخذه النموذج. دعم صورة مرفقة من داخل النموذج السريع يحتاج إلى موفّر رؤية متوافق وتغيير عقد الرسائل، وليس مجرد تغيير regex.

## من الوكيل الكامل إلى AgentSky

هناك مسار AgentSky منفصل ومقصود، وليس هو نفسه `chat-fast`: الواجهة تتصل بـ`/api/agent/*` عبر `src/lib/agentsky/client.ts`، والخادم في `src/lib/agentsky/agentsky.server.ts` يستدعي AgentSky API/Gateway. الوكيل الأساسي الذي يُنشأ للمستخدم يستخدم OpenClaw harness واسم النموذج المعرّف في الشيفرة `gpt-5.6-luna`، مع قدرات `exa.search` و`exa.contents` و`tinyfish.fetch` و`tinyfish.browser`. وكلاء المستخدمين والقوالب المخصصة يحتفظون بهويتهم ونموذج القالب عند إنشائهم. وكيل الوسائط Higgsfield/Hypit مستقل ومحصور بالوسائط.

بروتوكول AgentSky يرسل أحداث الجلسة من `/sessions/{id}/stream` إلى المتصفح كـSSE؛ `runAgentSkyTurn` يعيد بناء أحداث التفكير والأدوات والبطاقات، يعيد الاتصال عند انقطاع البث، ويصالح الأحداث مع سجل الجلسة دوريًا. الأداة وحدها لا تنشأ في الواجهة: الخادم يربط MCP موقّعًا لكل مستخدم، وتتحقق واجهة الأدوات من صلاحية الرمز والخطة.

عند عطل AgentSky المؤقت (شبكة، timeout، `408/425/429` أو `5xx`)، يعيد التطبيق الاتصال لفترة محدودة ثم يجرّب خدمة Computer Agent الموجودة داخليًا، والتي تعمل عبر Browser Use Cloud API ومفاتيح الخادم الدوّارة. لا يفتح التطبيق صفحة `cloud.browser-use.com/signin` ولا يطلب تسجيل دخول يدويًا. لا يُعاد تشغيل المهمة إذا كان AgentSky قد أظهر ردًا أو نفّذ خطوة فعلية، ولا يُستخدم Browser Use لتجاوز رفض صلاحيات/خطة أو فشل توليد صورة/فيديو. إذا تعذر fallback نفسه، يظهر الخطأ بدل الدوران إلى ما لا نهاية.

## أدوات AgentSky الظاهرة عبر MCP

| الأداة | الوظيفة |
|---|---|
| `generate_image` | إنشاء/تحرير صورة؛ النتيجة تظهر كبطاقة وسائط. النموذج المحدد في الشيفرة `gemini-3.1-flash-image-preview` من Google، والخدمة تتطلب الخطة المدفوعة. |
| `generate_video` | بدء توليد فيديو قصير؛ النتيجة تظهر كبطاقة تشغيل. النموذج المحدد `wan2.7-t2v` من Wan، والخدمة تتطلب الخطة المدفوعة. |
| `ask_user` | سؤال تفاعلي بخيارات، ثم يتوقف الوكيل حتى يجيب المستخدم. |
| `create_task` | إضافة مهمة أو تذكير إلى قائمة المستخدم. |
| `update_plan` | عرض خطة خطوات للعمل الجاري وتحديث حالاتها. |
| `propose_agent` | اقتراح إعداد وكيل جديد دون إنشائه؛ يحتاج المستخدم أن يوافق من بطاقة الاقتراح. |
| `megsy_card` | عرض بيانات بصريًا/تفاعليًا كبطاقة مثل جدول أو خريطة أو مخطط أو نموذج. |
| `show_service_result` | عرض نتيجة إجراء تم عبر خدمة موصولة كبطاقة واضحة. |
| `share_file` | حفظ ملف ناتج وإظهاره للمستخدم كبطاقة تنزيل. |

إضافةً إلى أدوات Megsy المذكورة، قد تتوفر أدوات خدمات موصولة عبر تكاملات/MCP بحسب إعداد حساب المستخدم. لا تُفترض صلاحيتها أو اتصالها لمجرد وجودها في كتالوج التطبيق.

## النموذج السريع مقابل مسار الدردشة الكامل

| المسار | الدور | النموذج/التنفيذ حسب المصدر |
|---|---|---|
| Fast Chat | نقطة البداية للرسائل النصية العادية؛ يجيب بسرعة أو يقرر التصعيد | Cerebras `gpt-oss-120b`؛ قد توجد استعادة إلى `chat-alibaba` عند تعذر مزوّد fast، وفق `callAgentFallback`. |
| Full chat | إكمال المهام التي تحتاج أدوات بعد قرار fast، أو خدمة الأوضاع المتخصصة | `supabase/functions/chat-alibaba/index.ts` يدير التنفيذ ويستعمل `callCerebras` أو استعادة Agent fallback. النموذج الفعلي يُمرّر في metadata/ترويسة الاستجابة؛ لا ينبغي افتراضه من اسم الواجهة وحده. |
| AgentSky/OpenClaw | جلسات الوكيل الدائمة، الأدوات الشخصية، أحداث الخطوات والبطاقات | `AGENT_MODEL = "gpt-5.6-luna"` في `agentsky.server.ts`؛ القوالب والوكلاء المخصصون يمكن أن يحددا `llm` مختلفًا. |
| وسائط AgentSky | تشغيل صور/فيديو عبر AgentSky Gateway | صورة `gemini-3.1-flash-image-preview`؛ فيديو `wan2.7-t2v`، مع حواجز الخطة/التكلفة. |

> الأسماء هنا هي إعدادات المصدر. لا يثبت فحص المستودع وحده أن مفاتيح المزوّد أو الخدمة الخارجية تعمل في الإنتاج الآن.

## ما كان يسبب التوجيه الخاطئ أو البث الناقص

كان `shouldUseFastChat` يرفض طلب الوسائط بمجرد مطابقة `detectMediaIntent`. وفوق ذلك كان `ChatPage` يرسل كل رسالة عادية تقريبًا إلى `runComputerTurn` قبل الوصول إلى Fast Chat، كما كان يلتقط طلبات الصور/الفيديو إلى مولّد مباشر ويحوّل طلبات البحث العميق نصيًا قبل أن يراها النموذج. أزيلت هذه المسارات الاستباقية من الدردشة العادية؛ الرسالة النصية العادية تبدأ الآن من Fast Agent، بينما أوضاع المستخدم الصريحة والوكيل المحدد يظلون على مساراتهم.

وكان محلل SSE يتطلب حرفيًا `data: ` بمسافة واحدة، وقد يهمل آخر إطار إذا أغلق الخادم الاتصال دون newline. أصبح يقبل `data:` و`data: ` ويحلل الإطار الأخير؛ كما يُمرّر reasoning منفصلًا عن نص الرد ويعاد تفعيل حالة التفكير عند وصوله. لا يكشف ذلك سلسلة التفكير الخاصة للنموذج كنص عادي؛ تبقى أحداث reasoning فقط ضمن مكوّن/بيانات التفكير في التطبيق.
